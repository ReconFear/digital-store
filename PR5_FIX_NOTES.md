**Статус: на повторное ревью, PR5 не принят.** Основная база `digital_store` не использовалась. Миграции 0000–0003 и `frontend/` побайтно не изменены. Push, merge и коммитов не было.

## 1. Разделение строк файла импорта

**Дефект подтверждён.** `read_codes_file()` вызывал `str.splitlines()`, а он режет строку по U+2028/U+2029, U+0085, VT, FF и FS/GS/RS ещё до `normalize_code()`. Поэтому один код с таким символом внутри превращался в два ключа.

**Исправление** (`commerce/digital_keys/importer.py`):

- Разделители строк — только `\r\n`, `\n` и одиночный `\r` (регулярное выражение `split_lines()`). Файл открывается с `newline=""`, BOM снимается (`utf-8-sig`).
- Остальные разрывы остаются внутри строки. `normalize_code()` отклоняет их как управляющие или невидимые символы, и вся партия не загружается. В отчёте — номер строки без значения.

**Тесты** (`tests/test_digital_keys.py`):

- U+2028, U+2029, U+0085, VT, FF, FS, RS внутри кода → `ImportProblem` «строка 2», значение в сообщение не попадает (7 случаев);
- окончания CRLF (Windows), LF и CR, а также BOM с пустой строкой → те же три ключа (4 случая);
- номера строк соответствуют файлу при пустых строках.

## 2. Одна версия секрета отпечатков на склад

**Дефект подтверждён.** `UNIQUE(fingerprint)` не видит повтор кода под другим секретом HMAC, а регистрация новой версии отпечатков была разрешена.

**Исправление** — в базе, в транзакции импорта (`digital_keys_import_core`, миграция 0004). Обходом CLI проверку не миновать:

1. После блокировки строки товара берётся **глобальная advisory-блокировка импорта**. Импорты идут строго по очереди, поэтому два одновременных «первых» импорта под разными версиями невозможны. Другие пути эту блокировку не берут, а порядок такой: товар → блокировка импорта.
2. Если в `digital_keys` есть хоть один ключ любого статуса (включая изъятые) с другой `fingerprint_key_id` — `RAISE`: «на складе есть ключи с отпечатками версии …; импорт под версией … запрещён (ротация секрета отпечатков не поддерживается)».
3. На пустом складе первая версия может быть любой зарегистрированной.
4. Версия ключа шифрования AES-GCM от этой проверки не зависит.

**Побочный эффект (улучшение):** одновременный импорт одного кода в два товара раньше давал второму ошибку уникальности `23505`. Теперь второй ждёт первый и получает обычный отчёт о дубликате.

**Тесты.** Проверки 1–4 и 6 идут в отдельной временной схеме с изначально пустым складом:
